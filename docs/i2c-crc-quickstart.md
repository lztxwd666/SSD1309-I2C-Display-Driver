# 自定义 I2C 接收端速查（v3）

供 MCU 桥接器和模拟器开发者适配当前 Rust / Python 驱动。完整时序、状态码和重试规则见 [v3 协议规范](i2c-crc-protocol.md)。旧版见 [v2 速查](i2c-crc-quickstart-v2.md)。

## 1. 线上格式

| 事务   | 线上字节                                                        | 大小                     |
| ------ | --------------------------------------------------------------- | ------------------------ |
| 主机写 | `type + len + seq_L + seq_H + payload + CRC_L + CRC_H`          | `len + 6`，最大 261 字节 |
| 主机读 | `flags + last_ok_seq_L + last_ok_seq_H + value + CRC_L + CRC_H` | 固定 6 字节              |

- 写和读以 STOP 分隔，直接读回执，无需先写读取选择字节。校验结果在 STOP 后通过回执返回。
- CRC-16/MODBUS 覆盖帧内 CRC 之前的所有字节，序号和 CRC 都是低字节在前。检查值 `"123456789" → 0x4B37`。
- `type=0x00` 为命令，`0x40` 为数据，载荷均为 1–255 字节。转发给 SSD1309 时只发送原控制字节和载荷。
- `type=0x01` 读取面板状态寄存器，长度为 0，成功回执的 `value` 为面板原始状态字节。
- `type=0x7F` 为同步，长度和序号均为 0。

## 2. 接收与回执

1. 启动后提供 `NEED_SYNC` 回执。合法的 `SYNC` 在空闲时建立会话，返回 `SYNCED`，普通帧从序号 1 开始。
2. 从匹配本设备的写地址开始计时。使用一个最大 261 字节的缓冲接收写帧，收到 STOP 后依次核对实际长度、CRC、类型和序号。提前 STOP 按格式错误处理，未及时收到 STOP 则丢弃半帧并复位解析。repeated START 中断写入时不得提交。
3. 旧帧仍占用缓冲时，从新事务开始就边收边弃，排空 FIFO，在 STOP 后给出 `BUSY_DROP`。帧超过实际容量或 FIFO 溢出时报告 `RX_OVERFLOW`。
4. 合法普通帧以期望序号处理。命令或数据完整转发成功后才记录 `OK`。同一成功序号的重发只返回原结果，面板查询也复用原样本。序号按 16 位回绕。
5. `flags` 的 bit 7 表示最近成功记录有效，bit 6 表示处理尚未结束，低 6 位为状态码。任何读事务都从回执第一个字节开始，读取不清除回执，接收错误也保留最近成功序号与状态样本。
6. 下游结果未知或收到越序普通帧时，锁存恢复状态，等待合法 `SYNC`。主机同步后重新初始化面板，避免基于未知的页列地址继续写数据。

主机一次只保留一笔未确认的写帧。回执的长度和 CRC 通过校验、成功序号匹配后才确认。回执损坏或 I2C 事务超时优先重读，重发使用原序号和原字节，超过总时限停止。接收、回执发布、结果及重试时间见 [完整规范](i2c-crc-protocol.md#7-时限与联调基线)。

## 3. 一致性向量

| 事务                                             | 预期                                            |
| ------------------------------------------------ | ----------------------------------------------- |
| 从机刚启动时读取                                 | `00 00 00 00 00 24`                             |
| 写 `7F 00 00 00 19 F0`，等待同步完成后读取       | `01 00 00 00 01 D8`                             |
| 写 `00 01 01 00 AE F5 80`                        | 转发 `00 AE`，回执 `83 01 00 00 78 60`          |
| 重发上面的命令                                   | 回执相同，转发次数仍为 1                        |
| 写 `40 02 02 00 01 02 F6 F3`（序号 2，CRC 错误） | STOP 后回执 `84 01 00 00 79 14`，成功序号仍为 1 |
| 重发正确的数据帧 `40 02 02 00 01 02 F6 F2`       | 回执 `83 02 00 00 88 60`                        |
| 写 `01 00 03 00 01 28`，面板返回 `81`            | 回执 `83 03 00 81 19 C0`                        |

联调时优先验证坏 CRC 回执的重读、已转发帧的重复发送、忙时丢弃、丢失 STOP、序号回绕和重启同步。用逻辑分析仪确认 CRC 错误通过独立读事务报告。
