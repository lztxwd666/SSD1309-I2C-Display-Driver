# 自定义 I2C 对端适配速查（协议 v2）

给接收端开发者（MCU 桥接器 / 模拟器）的精简适配说明。完整规范、边界条件与参考实现见 [i2c-crc-protocol.md](i2c-crc-protocol.md)。

> 原生 SSD1309 面板不支持本协议。对端必须校验并剥离长度字节与 CRC，再把剩余内容转发给面板；否则面板会把它们当成命令/数据显示。

## 1. 线上帧格式

| 帧         | 主机发出的字节                                   | CRC 覆盖                     |
| ---------- | ------------------------------------------------ | ---------------------------- |
| 命令帧     | `0x00` + `len` + 命令字节 + `CRC_L` + `CRC_H`    | `0x00` + `len` + 命令字节    |
| 数据帧     | `0x40` + `len` + GDDRAM 字节 + `CRC_L` + `CRC_H` | `0x40` + `len` + GDDRAM 字节 |
| 状态读请求 | `00 00 01 B0`                                    | 前 2 字节 `00 00`            |

- `len` = 载荷字节数（0..=255）；写帧总长度 = `len + 4`。
- CRC 低字节在前。
- 状态读响应为 3 字节：`状态字节 + CRC_L + CRC_H`，CRC 只覆盖状态字节。
- 只有 `0x00`（命令）和 `0x40`（数据）是合法控制字节。

## 2. CRC16

CRC-16/MODBUS：多项式 0x8005（反射 0xA001）、初值 0xFFFF、输入/输出反射、最终不取反。检查值：`"123456789"` → **0x4B37**。

可直接使用的最小 C 实现：

```c
uint16_t crc16(const uint8_t *p, size_t n) {
    uint16_t crc = 0xFFFF;
    for (size_t i = 0; i < n; i++) {
        crc ^= p[i];
        for (int b = 0; b < 8; b++)
            crc = (crc & 1) ? (crc >> 1) ^ 0xA001 : crc >> 1;
    }
    return crc;
}
```

## 3. 接收端必须做的事

### 写事务

1. 完整缓存一次写事务，直到 STOP；不要边收边转发。
2. 从第 2 个字节读出 `len`，计算帧总长 `len + 4`。
3. 在最后一个字节（`CRC_H`）的 ACK 周期：
   - 校验控制字节合法、收到字节数正确、CRC 正确。
   - 任一项失败：**NACK 最后一个字节**，整帧丢弃，不执行任何部分。
   - 全部通过：ACK，收到 STOP 后执行。
4. 校验通过后：
   - `控制=0x00` 且 `len=0`：状态读请求，置 pending 读标志，不执行命令。
   - `控制=0x00` 且 `len>0`：去掉长度字节和末尾 2 字节 CRC，把 `00 + 命令字节` 转发给面板。
   - `控制=0x40`：去掉长度字节和末尾 2 字节 CRC，把 `40 + 数据` 转发给面板。
   - 其他控制字节：丢弃。
5. 任何新的写事务都先清除 pending 读标志。

### 读事务

主机先在写事务里发送 `00 00 01 B0`，STOP 后再单独读取 3 字节：

- 收到合法读请求：置 pending，采样/缓存面板状态。
- 主机读取时返回 `状态字节 + CRC_L + CRC_H`，然后清除 pending。
- 状态 0x01 的响应为 `01 7E 80`；状态 0x81 为 `81 7F 20`。

### 转发规则

| 收到             | 校验通过后                       |
| ---------------- | -------------------------------- |
| `00 len ... CRC` | 转发 `00 ...`（去掉 len 和 CRC） |
| `40 len ... CRC` | 转发 `40 ...`（去掉 len 和 CRC） |
| `00 00 01 B0`    | 不转发；按状态读请求处理         |

## 4. 错误处理

| 情况                   | 接收端行为                           |
| ---------------------- | ------------------------------------ |
| CRC 错误               | NACK `CRC_H`，丢弃整帧               |
| 控制字节非法           | NACK `CRC_H`，丢弃整帧               |
| `len + 4` 超过缓冲上限 | 在 `len` 字节的 ACK 周期 NACK，丢弃  |
| STOP 早于帧尾          | 丢弃并记录长度错误；STOP 后无法 NACK |
| 收到超过帧尾的多余字节 | NACK 第一个多余字节，丢弃整帧        |
| 读请求 CRC 错误        | NACK，不置 pending                   |

发送端对 NACK 会自动重试 2 次；重试帧按全新帧处理。CRC 失败帧绝不能执行。

## 5. 一致性测试向量

| 完整帧                | 期望                |
| --------------------- | ------------------- |
| `00 01 AE F1 EC`      | ACK，执行命令 `AE`  |
| `00 01 AE F1 ED`      | CRC 失败，NACK      |
| `00 02 81 CF 81 E0`   | ACK，执行 `81 CF`   |
| `40 02 01 02 34 75`   | ACK，写数据 `01 02` |
| `40 02 01 02 34 76`   | CRC 失败，NACK      |
| `00 00 01 B0`         | ACK，置 pending 读  |
| `00 00 01 B1`         | CRC 失败，NACK      |
| `41 00 31 E0`         | 控制字节非法，NACK  |
| 主机读且 pending=0x01 | 返回 `01 7E 80`     |
| 主机读且 pending=0x81 | 返回 `81 7F 20`     |

## 6. 对端自检清单

- [ ] CRC 检查值 `"123456789"` = 0x4B37
- [ ] 按 `len + 4` 计算帧尾，按低字节在前读 CRC
- [ ] 在 `CRC_H` 的 ACK 周期 NACK 校验失败帧
- [ ] CRC 失败帧不执行任何部分；成功时收到 STOP 后再执行
- [ ] 识别 `00 00 01 B0` 为读请求，而不是空命令
- [ ] 状态读响应返回恰好 3 字节
- [ ] 不把 `len` 或 CRC 字节转发给面板
- [ ] 至少支持 259 字节写帧缓存
- [ ] 重试帧按全新帧处理

## 7. 联调

1. 先用第 5 节向量做静态解析测试。
2. 用逻辑分析仪确认：正常帧 ACK，破坏 CRC 的帧在最后一字节 NACK。
3. 接面板跑驱动的 `smoke` / `selftest` / `diag`，确认显示与状态读取正常。
